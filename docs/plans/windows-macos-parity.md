# Windows 版桌宠与 macOS 行为对齐规划

## 目标与边界

Windows 版使用与 macOS 相同的 `companion/Resources/pet` 页面、桥接协议和
DeepSeek Harness 会话；Windows 原生层只负责窗口、输入、贴边、截图和生命周期。
macOS 的 `PetWindow.swift` 是行为基线，Windows 不复制 AppKit API，而是实现等价的
状态和验收结果。

本计划只描述 Windows 版桌宠插件的开发顺序和验收标准。仓库中的任务文档属于
实现参考，不替代用户对功能和交付方式的要求。

## 共享行为基线

| 能力 | macOS 基线 | Windows 对等实现 | 验收结果 |
| --- | --- | --- | --- |
| 点击 | 紧凑态点击桌宠打开输入框；贴边态先弹回 | WebView 点击事件 + 原生恢复状态 | 单击不启动拖动、不闪避；输入框出现 |
| 拖动 | 鼠标移动超过阈值后移动窗口 | JS 判定阈值后调用 `start_dragging` | 小幅移动仍算点击；明显移动可拖动 |
| 贴边 | 左、右、底部贴边，只保留尾部 | 定时器检测屏幕边缘，保存恢复位置 | 松手靠近边缘后自动隐藏，恢复位置不丢 |
| 恢复 | 鼠标进入热区弹回；贴边点击先弹回 | `GetCursorPos` 轮询恢复；恢复后设置 hold | 进入热区只恢复一次，恢复后点击不再次隐藏 |
| 对话布局 | compact/chat 两种布局；聊天时不自动贴边 | 复用 `layout` 消息调整 Tauri 窗口 | 气泡、输入框、按钮不被窗口裁切 |
| 历史滚动 | 用户上滑时保持当前位置；仅接近底部才跟随 | 复用 `transcriptFollowTail` | 上滑查看历史不会被流式更新弹回底部 |
| 截图 | 用户主动框选，确认后才提交视觉请求 | Windows 屏幕捕获选择层 + `/api/pet/vision` | Esc 可取消；框选后输入问题再识别 |
| 配置 | 插件配置页保存本地凭据 | Windows/macOS 共用本地 env 与 MCP patch | 配置状态、uvx 预检和实际 MCP 状态一致 |

## 阶段 1：窗口与命中测试

### 实现

- 保持无边框、透明、置顶窗口，关闭系统阴影和装饰性空白区域。
- `WM_NCHITTEST` 对桌宠、气泡、输入框和按钮返回客户端命中；透明空白区域返回
  `HTTRANSPARENT`，不遮挡 Harness。
- 贴边恢复条保持客户端命中，避免 `HTCAPTION` 在桌宠本体上抢先触发原生拖动。
- 前端 `mousedown` 记录屏幕坐标，超过 6px 才发送 `drag`。

### 验收

- 普通点击桌宠只打开输入框，不移动窗口。
- 鼠标触碰、悬停和小幅抖动不改变窗口位置。
- 空白透明区域仍可点击到后面的 Harness。
- 气泡、输入框、截图、发送和停止按钮可独立点击。

### 测试

- release 构建后逐项执行点击、小幅移动和明显拖动。
- 检查 `WM_NCHITTEST` 代码路径和前端 `postHitRegions` 是否同步。
- 覆盖窗口刚启动、布局刚切换和贴边恢复条尚未收到首个布局消息的时序。

## 阶段 2：贴边与恢复状态机

### 实现

- 状态固定为 `free`、`docked`、`recovering` 三种逻辑状态；`restore_position` 只保存
  最近一次完整可见位置。
- 自动贴边只在鼠标按钮释放、聊天未打开且用户未处于恢复 hold 时执行。
- 恢复后鼠标离开边缘热区才清除 hold，防止同一动作立即再次贴边。
- 多显示器使用虚拟屏幕边界，恢复条在左、右、上、下边界都保留可见区域。

### 验收

- 从屏幕中央拖到左、右、上、下边缘均能隐藏。
- 鼠标进入边缘热区只弹回一次。
- 弹回后点击、输入和再次拖动均不会瞬间隐藏。
- 关闭自动贴边后窗口立即回到完整位置；打开后仍可再次贴边。
- 打开聊天或流式回复期间不自动隐藏。

### 测试

- 单显示器、负坐标副屏和不同 DPI 缩放各执行一次。
- 记录窗口外框位置、尺寸和恢复位置，确认没有负向漂移或不可见状态。

## 阶段 3：聊天布局、历史滚动与流式状态

### 实现

- compact 状态只包住桌宠；chat 状态为气泡和输入栏预留空间。
- 调整窗口尺寸时根据当前贴边方向锚定边缘，避免窗口跳到屏幕中央。
- 历史面板使用“接近底部才跟随”的规则；用户上滑后，增量渲染不修改
  `scrollTop`。
- 会话状态、活动状态、取消任务和离线状态继续通过同一条桥接事件投影。

### 验收

- 上滑查看旧消息时流式回复继续渲染，但视口不被拉到底部。
- 回到底部后，后续增量重新跟随最新消息。
- 关闭气泡不会清空历史；重新打开仍保留上下文。
- 桌面端发起任务时桌宠进入聊天布局，完成后恢复正确状态。

### 测试

- 至少生成超过一屏的历史消息，分别测试静态历史、流式更新和轮询刷新。
- 检查窗口尺寸变化前后的滚动位置和贴边锚点。

## 阶段 4：截图选择器与视觉 MCP

### 实现

- 点击截图按钮才打开一次性区域选择层；Esc 或取消不产生视觉请求。
- 选区使用虚拟屏幕坐标和 DPI 缩放，确认后由 Rust 捕获 JPEG 并暂存。
- 发送问题时才调用 `/api/pet/vision`，图片临时保存到 DSH home 下并自动清理。
- 配置页读取本地 `pet-qwen-mm.env`、`QWEN_MM_CONFIG` 和兼容环境变量，但不向浏览器
  返回 API Key。
- MCP patch 使用跨平台 `uvx` 命令和 `QWEN_MM_CONFIG` 环境变量；实际 profile 必须
  合并该 patch 并重启 Harness。

### 验收

- 配置存在时显示已配置、Key 末四位和 uvx 预检状态。
- 配置缺失、uvx 缺失、MCP 尚未重启三种状态分别给出明确提示。
- 框选、取消、提交视觉问题和 MCP 工具失败均有可读反馈，不编造图像内容。

### 测试

- `/api/pet/vision/settings` GET/POST 各测一次，确认响应不含密钥。
- 使用真实 `uvx` 启动 MCP，验证工具列表可见；再用一张本地截图验证视觉请求链路。

## 阶段 5：插件配置卡与桥接生命周期

### 实现

- 配置卡保存通用偏好、视觉凭据和伴生应用路径。
- profile 启动时写入带 `instanceId` 和过期时间的 bridge 文件；桌宠只连接当前实例。
- DSH 重启、插件热更新、桌宠退出和桥接过期都必须清理旧状态。
- 配置卡与桌宠状态共用 `/api/pet/preferences`、`/api/pet/status` 和视觉设置路由。

### 验收

- 插件列表中的配置入口始终存在，保存后重启仍可读取。
- DSH 重启不会创建第二个桌宠或第二条 Agent 会话。
- Harness 关闭后桌宠隐藏；恢复后能重新连接并同步历史和偏好。

## 阶段 6：安装包、启动、升级与回归

### 实现

- 固定 Windows companion 的应用 ID、安装路径和默认启动参数。
- 生成 NSIS/MSI 安装包，发布前校验 SHA-256；开发模式允许从 checkout 启动。
- 安装包升级保留桌宠偏好、视觉配置和会话历史，不覆盖 DSH home。
- GitHub Actions 在 Windows runner 上构建并上传产物；分支本地先完成实机回归。

### 最终验收矩阵

| 场景 | 结果 |
| --- | --- |
| 启动、退出、重启 Harness | 桌宠生命周期正确，无重复窗口 |
| 普通点击与拖动 | 点击不闪避，拖动阈值稳定 |
| 四边贴边与恢复 | 可隐藏、可恢复、可拖离 |
| 聊天和历史滚动 | 上滑不回底，流式状态正确 |
| 截图和视觉 MCP | 配置可见、选区可用、工具真实调用 |
| 插件配置与偏好 | 入口存在，保存后重启仍生效 |
| 安装包和升级 | 可安装、可启动、数据不丢 |
